# 우리 가족 카페

수도권 대형·베이커리 카페를 자동으로 모아 **매주 10곳을 추천**하는 가족 전용 웹서비스.

인천 부평에 사는 4인 가족이 월 2회 주말 나들이를 정하는 데 쓴다. 아내가 인스타에서
카페를 발견하고, 흩어진 그것들을 주말마다 다시 고민하던 문제를 푼다.

```
매일   블로그 화제량 수집 -> 뜨는 곳 갱신
매주   신규 발굴 -> 판정 -> 주말 후보 10곳
금요일 정오  카카오톡으로 링크가 온다
가족   다녀왔어요 체크 · 별점(반개 단위) · 한 줄 후기
```

## 무엇이 특별한가

**크롤링을 하지 않는다.** 인스타는 로그인 없이 아무것도 못 보므로, 크롤링한다는 것은
곧 정지될 계정을 만든다는 뜻이다. 대신 한국인의 행동 패턴을 쓴다 — 인스타에서 보고,
네이버에 검색하고, 블로그 후기가 쏟아진다. **블로그 포스팅 가속도**가 바이럴의 대리
지표가 된다. 1~2주 후행하지만 월 2회 가는 가족에게는 손실이 없다.

**주차가 게이트다.** 차로만 이동하므로 주차 불가는 다른 장점을 전부 무효화한다.
후기에 적힌 내용만 믿고, "1시간 무료" 같은 조건부는 넉넉하다고 보지 않는다.

**동네 카페 = 성격 태그 0개.** 별도 판별기를 만들지 않았다. 넣고 싶은 것을 정의하면
뺄 것은 자동으로 정의된다.

**별점 저장소는 GitHub 다. DB 가 없다.** Supabase 무료 티어는 7일 미사용 시
프로젝트를 정지시키는데 이 앱은 월 2회 쓴다 — 누르려는 순간 정지 화면을 만난다.
데이터가 이미 git 에 있으니 별점도 같은 곳에 둔다. 동시 수정은 `sha` 불일치로
감지해 다시 읽어 합친다.

## 구조

```
src/
  sources/     카카오 장소·블로그·길찾기 어댑터 (레이트리밋·재시도·헬스)
  pipeline/    판정 로직. 전부 순수 함수 — I/O 도 Date.now() 도 없다
  llm/         Gemini / Anthropic. .env 한 줄로 교체
  jobs/        레이어를 순서대로 호출해 상태를 확정하는 배치
  site/        웹앱이 읽을 표시용 페이로드 생성
  cli/         운영 도구. 웹 관리 화면을 만들지 않았다
data/          JSON in git. DB 없음. zod 가 스키마의 단일 진실 원천
web/           Next.js. 화면은 전부 정적 생성. 쓰기는 별점·방문 두 경로뿐
```

5단 퍼널로 걸러낸다.

| 레이어 | 하는 일 | 비용 |
|---|---|---|
| 0 수집 | 키워드 검색 + 블로그 큐레이션 수확 | 카카오 |
| 1 하드 배제 | 프랜차이즈·테마카페·타지역 | 0 (규칙) |
| 2 화제량 컷 | 정밀도 30% · 월 8건 | 카카오 |
| 3 속성 추출 | 규모·주차·메뉴·뷰를 후기에서 | **LLM** |
| 4 태그 | 성격 태그 8종 | 0 (규칙) |
| 5 게이트 | 태그 0개 / 주차 불가 배제 | 0 (규칙) |

**Layer 2 를 LLM 앞에 둔다.** 통과율이 약 20% 라 LLM 호출이 1/5 로 줄어든다.

## 설정

`.env` 두 줄이면 된다.

```
KAKAO_REST_API_KEY=...     # 카카오 개발자센터. 카카오맵 제품 설정 ON 필요
GEMINI_API_KEY=...         # aistudio.google.com/apikey
```

`npm run check-keys` 로 확인한다.

웹앱은 환경변수 두 개를 더 본다. 없으면 **그 기능만 꺼지고 화면은 돈다.**

```
GITHUB_TOKEN    별점·방문 저장. 없으면 로컬 파일로 폴백한다
GITHUB_REPO     owner/name
```

접근 코드는 두지 않는다 — 내용이 카페 목록이고 개인정보가 없다. `robots.txt`
로 색인만 차단한다 (스펙 10절).

## 사용량 감시

`npm run watch` 가 **증상**을 본다 (무료 티어는 사용량 조회 API 가 없다).

| 검사 | 수준 | 잡는 것 |
|---|---|---|
| 추천 대상(active) 오늘 측정 < 80% | 경보 | 카카오 수집 고장 |
| 오늘 측정 총량 < 기대치 30% | 경보 | 수집 조기 중단 |
| 대기가 남았는데 오늘 판정 0곳 | 경보 | Gemini 쿼터를 남이 쓰는 신호 |
| 소스 연속 실패 3회 이상 | 경보 | 소스 장애 |
| 매일 도는 소스가 36시간 침묵 | 경보 | 크론·워크플로 고장 |
| 쿼터 오류(429·RESOURCE_EXHAUSTED) | 경고 | **무료 티어에서는 정상** |
| 오늘 판정 50곳 미만 | 경고 | 쿼터가 일찍 끊김 |

**쿼터 오류 자체는 경보가 아니다.** 무료 티어에서 하루 한도까지 쓰면 429 는 매일
온다. 그걸로 매일 메일을 보내면 사흘 뒤부터 아무도 열지 않는다. 키가 새서 남이
쓰는 경우는 "429 가 왔다" 가 아니라 **"한 곳도 못 했다"** 로 드러난다.

경보가 하나라도 있으면 **exit 1** 로 끝난다. `daily-watch` 워크플로가 매일
07:40 KST 에 돌고, 실패하면 GitHub 이 계정 메일로 알린다 — PC 가 꺼져 있어도
닿는 경로다. 금요일 정오 카톡에도 상태가 한 줄 붙는다 (`자동수집 정상`).

**감시에는 API 키를 주지 않는다.** 감시가 키에 의존하면 키가 문제일 때 감시부터
죽는다.

## 정합성 감사

```bash
npm run audit        # 데이터가 틀렸나 (키 없이 돈다)
npm run watch        # 운영이 멈췄나 (키 없이 돈다)
npm run normalize    # 시군구를 주소 기준으로 정정 (멱등)
```

`watch` 와 `audit` 은 역할이 다르다. **watch 는 운영 이상**(수집이 멈췄나,
쿼터가 끊겼나)을 보고 매일 자동으로 돈다. **audit 은 데이터 정합성**(표시가
틀렸나, 규칙이 깨졌나)을 보고 사람이 돌린다.

audit 이 잡는 것 — 같은 카페 중복, 게이트 위반, 시군구가 주소와 불일치,
방향 배정이 시도와 불일치, 추천에 주차 어려운 곳, 한 지역 3곳 이상,
근거 인용 누락, 추천 대상 화제량 노후. 검증 3회에서 실제로 걸린 것들이
그대로 규칙이 됐다.

## 데이터 커밋 (Actions)

잡이 만든 데이터는 `scripts/commit-data.sh` 한 곳에서 커밋·푸시한다. 이 일이
두 번 깨졌고 깨진 곳이 다섯 군데였다.

| 실패 | 원인 |
|---|---|
| 다섯 잡 전부 커밋 단계에서 죽음 | 커밋 **전에** `git pull --rebase` 를 불렀다 |
| 38분 걸린 발굴 잡이 죽음 | 그 사이 다른 잡이 `site.json` 을 밀어 병합 충돌 |

규칙은 하나다. **생성물은 병합하지 않는다. 다시 만든다.**
`web/src/generated/site.json` 은 `data/` 에서 계산되는 파생물이라, 합쳐진 JSON 은
어느 쪽 데이터와도 일치하지 않는다. 그래서 원격 것을 받고, 데이터를 정렬한 뒤,
마지막에 다시 생성한다.

반대로 `data/` 충돌은 **실패로 끝낸다.** 두 잡이 같은 파일을 동시에 고쳤다는
뜻이고, 조용히 한쪽을 버리면 안 되는 상황이다.

두 경로 모두 시나리오 시험이 있다:

```bash
bash scripts/test-commit-data.sh "$PWD/scripts/commit-data.sh" /tmp/ct
```

## 쓰기 락

잡들이 각자 `cafes.json` 전체를 읽고 고쳐 다시 쓴다. 두 개가 겹치면 나중에 쓴 쪽이
앞선 쪽 작업을 날린다. 로컬은 `data/.lock`, GitHub Actions 는 concurrency group 으로
직렬화한다. `data/.lock` 이 남아 있으면 죽은 작업이므로 지워도 된다 (45분 지나면
자동으로 빼앗는다).
