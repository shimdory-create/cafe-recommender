## 송도·영종 건 — 카페가 없는 게 아니라 **판정을 못 하고 있었습니다**

수집은 진작 됐는데 심사 줄에서 계속 뒤로 밀리고 있었습니다.

```
송도    75곳 수집 -> 통과 10곳 (대기 59)
영종구  92곳 수집 -> 통과  7곳 (대기 76)
연수구 117곳 수집 -> 통과 14곳
```

### 원인 — 블로그 글 수로 줄을 세운 것

카페 한 곳을 심사하려면 AI 판정이 필요한데 무료 한도가 있어 하루 200곳씩만
합니다. 그 순서를 **블로그 글이 많은 순**으로 정해뒀습니다.

문제는 여기입니다. **블로그 글은 멀리 나들이 간 곳에 쓰입니다.** 집에서
25분 거리 카페는 글감이 안 되니 글이 적고, 그래서 줄 맨 뒤로 갑니다.

```
인천 대기분의 블로그 글 중앙값   월 1.0건
그날 심사 커트라인              월 8.1건
```

게다가 통과 기준 자체도 **월 8건 고정**이었습니다. 그 기준에 걸려 잘려나간
179곳 중 **123곳(69%)이 40분 이내**였습니다. 부평구 2분 거리 `빵고베이커리`가
월 5.5건으로 탈락해 있었습니다.

`월 8건`이 실제로 묻던 질문은 **"한 시간 넘게 운전할 만큼 뜨거운가"** 입니다.
25분 거리에 그걸 요구할 이유가 없습니다.

### 고친 것 셋

| | 내용 |
|---|---|
| 통과 기준 | 40분 이내 **월 4건** · 41~70분 6건 · 71분+ 8건 |
| 심사 순서 | 하루 몫의 30% 를 가까운 순으로 배정 |
| 화제량 측정 | 미측정분 중에서는 가까운 곳부터 (영종 66곳이 아예 측정 대기였음) |

기준을 낮췄지만 **품질은 그대로입니다.** 동네 카페를 걸러내는 것은 원래
화제량이 아니라 성격 태그(대형카페·뷰맛집 등 0개면 탈락)입니다. 골든셋
점검도 기준선 그대로였습니다 — 오통과율 5%, 경계 통과율 50%.

마지막 것만 가능했는데 넣지 않았습니다. **틀린 영업시간은 없는 것보다
나쁩니다** — 한 시간 운전해서 닫힌 문 앞에 섭니다.

대신 카페 화면에 **`영업시간·휴무일 확인`** 버튼을 크게 넣었습니다. 한 번
누르면 네이버지도에서 정확한 값이 나옵니다.

리뷰 수 자리에는 **우리가 직접 센 블로그 글 수**가 들어갑니다.

### 2. NEW 는 지금 0곳입니다

`8/19~21 사흘 동안 6,218곳을 한 번에 긁었기 때문`입니다. 그대로 30일 창에
넣으면 465곳이 **전부** NEW 가 되고, 전부에 붙은 배지는 아무 뜻이 없습니다.

그래서 **8/22 이후에 새로 발굴된 곳만** NEW 로 봅니다. 8/23 발굴분 270곳이

아예 안 보입니다.

### 3. NEW 는 "새로 문 연 곳" 이 아니라 "우리 목록에 새로 들어온 곳"

개업일을 주는 무료 API 가 없습니다. 뜻을 좁히는 편이 지어내는 것보다 낫다고
판단했습니다.

### 4. 별점 수정·삭제는 누가 남겼는지 확인하지 않습니다

인증이 없어서입니다 (처음부터 그런 설계입니다 — 4명이 쓰는 화면에 로그인을
붙이면 아무도 안 씁니다). 대신 두 가지를 뒀습니다.

- 지울 때 **누구 것인지 넣어 묻습니다** — `'김' 님이 남긴 별점 4.0점을 지울까요?`
- 그 폰에서 남긴 것에는 **`내가 남김`** 표시

즉 **가족끼리는 서로의 별점을 고칠 수 있습니다.** 이게 불편하시면 말씀해
주세요 — 자기 폰에서 남긴 것만 고칠 수 있게 좁힐 수 있습니다.

그건 **추정 발행률**입니다 — 최근 글이 이틀에 몰리면 한 달치로 부풀려집니다.

**점수 계산에는 발행률, 화면에는 실측**으로 갈랐습니다.
