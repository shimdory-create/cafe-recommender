## 1. 폐업한 카페를 아무도 보지 않았습니다

발굴 잡은 **새 카페만 넣습니다.** 이미 아는 id 는 그냥 지나갑니다. 그래서
카페가 문을 닫아도 우리 목록에는 영원히 남습니다 — 한 시간 운전해서 닫힌 문
앞에 서는 경로입니다.

화제량으로는 못 잡습니다. 블로그 글은 폐업 뒤에도 몇 달 남아 있습니다.

카카오 장소 검색은 폐업하면 결과에서 빠집니다. 그래서 **주 1회 다시
찾아보는** 작업을 만들었습니다. 21일 넘게 안 보이면 경고가 뜹니다.

**자동으로 지우지는 않습니다.** 검색 순위 밖으로 밀렸거나 상호가 바뀐 것일
수도 있어서, 멀쩡한 카페를 조용히 지우는 것보다 사람이 확인하는 편이 낫습니다.

첫 실행 결과: **1,044곳 중 1,042곳 확인.** 지금 폐업한 곳은 없습니다.

## 2. 그 확인이 더 큰 것을 드러냈습니다 — 지도 링크

못 찾은 2곳이 폐업이 아니었습니다. 검색어가 `시군구 + 상호`라서 **동명
지역**에 걸린 것이었습니다.

```
광주시 카페숨       →  전남 광주통합특별시 해남군 결과
경기 광주시 카페숨   →  정확히 찾음
```

**같은 검색어를 네이버지도 링크도 쓰고 있었습니다.** 강서구(서울·부산),
중구(여섯 곳), 광주시(경기 vs 광주광역시) — **54곳**이 엉뚱한 지역을 열 수
있었습니다. 가족이 직접 누르는 링크입니다.

시도를 붙였습니다. `경기 광주시 카페숨`, `서울 강서구 플라워플로우`.

## 3. 워크플로가 조용히 건너뛰었습니다

어제(8/24) **daily-classify 와 daily-watch 가 통째로 실행되지 않았습니다.**
실패가 아니라 GitHub 무료 스케줄러가 예약을 버린 것입니다.

```
실패    →  메일이 온다
안 돎   →  아무 데도 안 남는다
```

하루 누락은 정상 범위입니다(다음 날 이어서 처리). 이틀 연속이면 감시가
잡습니다. 문제는 **감시 자체가 안 돌면 그것도 조용하다**는 것이었습니다.

감시만 하루 두 번 시도하게 했습니다. 0.3분짜리라 비용이 없고, 감시가 살아
있으면 나머지 이상은 전부 잡힙니다.
