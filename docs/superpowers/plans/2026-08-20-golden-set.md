# 계획 2 — 골든셋 구축과 품질 보정

**Goal:** 파이프라인의 판정 품질을 숫자로 고정한다. 사람이 40곳에 O/X 를 누르면 오통과율·오탈락률·경계 정확도가 나오고, 그 뒤로는 프롬프트나 공식을 고칠 때마다 같은 40곳으로 회귀 검증한다.

**Why now:** 계획 1 로 파이프라인은 돌지만 **판정이 맞는지 아무도 모른다.** 태그 분포가 균일하게 나오는 것을 보고도 "양평 특성인지 관대한 임계인지" 구분할 수 없었다 (발견 B). 골든셋 없이 임계값을 만지는 것은 근거 없는 추측이다.

**Spec:** `docs/superpowers/specs/2026-08-19-cafe-recommender-design.md` 13.1절
**입력 문서:** `2026-08-20-pipeline-run-findings.md` (양평 9곳) · `2026-08-20-full-scan-findings.md` (전수 + 200곳)

## 현재 상태 (2026-08-20 밤)

```
발굴    6,216곳 / 64개 시군구
화제량  5,875곳 / Layer 2 통과 1,235곳 (21%)
판정    200곳 처리 -> 통과 19곳 / 배제 181곳
        p2 프롬프트로 55곳 재추출
```

`classify` 는 무료 티어 때문에 하루 200곳이 상한이다. GitHub Actions 가
매일 돌므로 1,235곳은 약 일주일에 소화된다. **골든셋은 기다리지 않는다** —
층화 추출에 200곳이면 충분하다.

## Task 4 — 측정값에 따른 보정 (라벨 이후)

라벨이 없으면 시작할 수 없다. 무엇을 고칠지는 숫자가 결정한다.

- [ ] **경계 통과율이 0.5 에서 멀면** 컷 위치를 옮긴다
  - O 쪽으로 치우침 -> 컷이 너무 높다. 좋은 곳을 버리고 있다
  - X 쪽으로 치우침 -> 컷이 너무 낮다. 동네 카페가 새고 있다
- [ ] **오탈락률이 높으면** Layer 2 의 구제 경로(발견 C)를 손댄다
- [ ] **X 이유 분포**가 우선순위를 정한다
  - `neighborhood` 多 -> Layer 2 컷 / Layer 4 임계
  - `parking` 多 -> p3 프롬프트에서 주차 규칙을 더 조인다
  - `too_small` 多 -> `scale` 추출 (현재 `seatsEstimate` 는 100% null)
  - `too_far` 多 -> `distance_decay` 계수 또는 실주행 시간 도입
- [ ] 고친 뒤 같은 40곳으로 회귀. 오통과율이 개선되었는지 숫자로 확인
