## 1. 네이버 검색 API — 신규 발급 경로가 사라졌다

### 무슨 일이 있었나

네이버가 **2026-06-25** 에 검색 API·Search Trend·쇼핑인사이트를 개발자센터에서
**NAVER API HUB (네이버 클라우드 플랫폼)** 으로 이관했다.

| 대상 | 상태 |
|---|---|
| 2026-07-30 까지 신청한 기존 사용자 | 2027-06-30 까지 기존 경로 사용 가능 |
| **신규 신청자 (우리)** | **NCP 계정 + API HUB 콘솔 필수. 종량제** |

증상: `developers.naver.com` 애플리케이션 등록 화면의 [사용 API] 드롭다운에
**"검색" 항목이 아예 없다.** 선택 가능한 항목은 네이버 로그인·인증서·전자문서·
네이버페이 배송지·카페·캘린더·캡차(음성)·캡차(이미지) 8개뿐이다.

### 스펙에 미치는 영향

스펙 6.3절은 "네이버 검색 API 무료 25,000회/일"을 전제로 HotScore 전체를
설계했다. **이 전제가 무효**다. NCP 종량제는 무료 티어가 불명확하고, 계정
가입이 추가로 필요해 유지보수 최소화 목표에도 어긋난다.

## 2. 대체 검증 — 카카오(다음) 블로그 검색으로 완전 대체 가능

이미 발급받아 동작 확인된 카카오 REST API 키로 `dapi.kakao.com/v2/search/blog`
를 호출했다. **추가 가입도, 추가 활성화도 필요 없었다.**

### 2-1. 첫 시도: `total_count` 는 쓸 수 없다

`query="{지역} {상호}"`, `sort=recency`, `size=50`:

| 검색어 | total_count |
|---|---|
| 양평 테라로사 | 22,607 |
| 파주 더티트렁크 | 25,838 |
| **망리단길없는카페이름12345** (존재하지 않음) | **3,434** |

전혀 다른 두 카페의 카운트가 거의 같고, **존재하지 않는 이름도 3,434를
받는다.** 다음 검색은 OR 매칭이라 카운트가 상호명이 아니라 지역명·일반어를
반영한다. 따옴표로 구문 검색을 시도해도 무시된다 (`"양평 테라로사"` 도 22,607).

**결론: `total_count` 를 BuzzVolume 근거로 쓰면 모든 카페가 같은 점수를 받는다.**

### 2-2. 해결: 문서를 직접 검증한다

받아온 50건에서 **상호명을 실제로 포함하는 문서만 남기고**, 그 문서들의
날짜 분포로 발행률을 계산한다.

| 카페 | 정밀도 | 관련수 | 기간 | 월 발행률 | 도메인 |
|---|---|---|---|---|---|
| 더티트렁크 (파주) | 86% | 43 | 18.7일 | **69건** | naver.com 42 |
| 테라로사 (양평) | 96% | 48 | 16.8일 | **86건** | naver.com 46 |
| 메가커피 (부평) | 56% | 28 | 16.0일 | 53건 | naver.com 28 |
| 수목원 (가평) | 100% | 50 | 2.4일 | 634건 | naver.com 39 |
| 존재안함카페 (옹진군) | **0%** | **0** | — | **0** | — |

확인된 사실:

1. **네이버 블로그가 충실히 색인된다** — 관련 문서의 대부분이 `naver.com`
   도메인이다 (42/46/39/28건). 다음 검색을 써도 네이버 블로그 신호를 얻는다.
   커버리지 우려가 해소되었다.
2. **음성 신호가 완벽하다** — 존재하지 않는 카페는 정밀도 0%, 관련수 0건.
   `total_count` 가 3,434를 주더라도 문서 검증이 걸러낸다.
3. **해상도가 충분하다** — 50건이 2.4일에 걸치면 월 634건, 18.7일이면 월 69건.
   **약 200배의 동적 범위**가 나온다.

### 2-3. 원래 설계보다 나은 점

| | 네이버 (원안) | 카카오 (개정안) |
|---|---|---|
| 신규 발급 | **불가** | 이미 보유 |
| 계정 수 | 카카오 + 네이버 | **카카오 하나** |
| 화제량 근거 | 불투명한 `total` 집계 | **문서를 직접 검증** |
| 동명이인 오염 | 지역명 조합으로 완화 | **정밀도로 자동 검출** |
| 비용 | 종량제 | 무료 쿼터 |

소스가 하나로 줄어 유지보수 부담이 감소한다.

### 2-4. 남은 리스크: 일반명사 상호명

`수목원` 이 월 634건으로 나왔다. 이는 카페가 아니라 "가평 수목원" 전반에
대한 글이다. **상호명이 일반명사면 정밀도 필터가 무력해진다.**

대응 (v3 에 반영):
- 관련성 판정에 상호명 **단독 포함이 아니라 `카페`·`베이커리`·`커피` 등
  카페 문맥어의 동시 출현**을 요구한다
- 상호명이 2글자 이하이거나 일반명사 사전에 있으면 신뢰도를 낮추고
  골든셋 경계 구간으로 보낸다

## 3. LLM — Anthropic API 대신 Gemini 무료 티어

Anthropic API 는 무료 티어가 없고 최소 $5 선불 충전이 필요하다 (예상 비용은
초기 1회 약 9,000원 + 월 약 400원으로 작지만, 무료 경로를 우선한다).

Google AI Studio 키는 결제 수단 없이 발급된다. 실제 추출 품질을 검증했다.

### 3-1. 모델 선택 — 실측

입력: 블로그 후기 한 단락. 출력: `responseSchema` 로 구조화 강제.

| 모델 | 응답시간 | 결과 |
|---|---|---|
| `gemini-3.6-flash` | **21,091ms** | 정답 |
| **`gemini-3.1-flash-lite`** | **1,890ms** | **정답 (3.6과 동일)** |
| `gemini-flash-latest` | 4,110ms | **HTTP 503 과부하** |
| `gemini-2.5-flash` | — | **HTTP 404 — 신규 사용자 차단** |

추출 결과 (두 모델 동일):

```json
{
  "scale": "대형",          "seats_estimate": 200,   "floors": 2,
  "has_bakery": true,       "bread_baked_onsite": true,
  "menu_level": 3,          "view_strength": 3,      "view_types": ["강"],
  "parking_grade": "A",
  "evidence": "2층 통창에 좌석 200석 넘고 주차장도 넓어서 ..."
}
```

`evidence` 인용까지 정확히 지켰다. 스펙 Layer 3 의 요구를 충족한다.

### 3-2. 결정

- **주력: `gemini-3.1-flash-lite`** — 3.6 과 답이 같으면서 **11배 빠르다.**
  1,200곳 추출이 7시간에서 38분으로 줄어든다
- **승급: `gemini-3.6-flash`** — `confidence` 가 낮거나 `evidence` 가 비었을 때만
- **별칭(`*-latest`) 금지** — 503 을 실제로 받았다. 버전을 고정하고
  `model_version` 에 기록한다 (스펙 Layer 3 재처리 판단용)

### 3-3. 설계 요구사항

LLM 클라이언트를 **provider-agnostic** 하게 만든다. `.env` 값 하나로
Gemini <-> Anthropic 을 바꿀 수 있어야 한다. 비용 판단이 바뀌거나 무료 티어
정책이 변하더라도 어댑터 교체로 끝나게 한다. 스펙 6.6절 어댑터 원칙의 연장이다.

초기 1,200곳 백필은 무료 티어의 일일 요청 한도에 걸릴 수 있다. 며칠에 걸쳐
나누어 돌리는 것을 전제로 설계한다 (일회성 작업이므로 수용 가능).

## 5. 미결 사항 — 저장소를 Supabase 로 할지 JSON 으로 할지

v2 개정으로 쓰기 기능이 "다녀왔어요" 토글 하나로 줄면서 DB 의 존재 이유가
약해졌다. 테이블 12개 중 11개가 읽기 전용 데이터다.

| | A. Supabase | B. JSON in git |
|---|---|---|
| 인프라 | 계정 + 프로젝트 + 스키마 | 없음 |
| 관리 키 | +2 (URL, service_role) | 0 |
| 스키마 변경 | SQL 실행 | zod 타입 수정 |
| 무료티어 정지 | 1주 미사용 시 | 해당 없음 |
| 웹 서버 로직 | 쓰기 엔드포인트 1개 | 0. 완전 정적 |
| 데이터 이력 | 별도 설계 필요 | git diff 로 공짜 |
| "다녀왔어요" | 웹에서 누구나 | CLI (아빠, 월 2회) |

카페 1,500곳 = 약 1.5MB. git 부담이 없고 전부 메모리에 올려 필터링 가능하다.
복잡한 쿼리가 하나도 없다.

**B 를 권한다.** 유일한 대가는 방문 기록을 아빠가 CLI 로 남기는 것이고,
월 2회 한 줄이다. B 로 결정되면 스펙 9·10·11절과 계획 Task 2 를 다시 쓴다.
나중에 마음이 바뀌어도 저장소 어댑터 교체로 A 로 옮길 수 있다.
