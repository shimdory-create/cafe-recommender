## 1. 측정값

```
              O    X    ?
상위 구간     10    0    0
중간대         9    1    0
경계 구간      5    5    0
자동 탈락      3    7    0

동네카페 오통과율   5%    (상위·중간대의 X 비율)
오탈락률           30%    (탈락 구간의 O 비율)
경계 구간 통과율   50%    (50% 에 가까우면 컷 위치가 적절)
```

**성공 기준 2("상위 20곳에 동네 카페 1곳 이하")를 정확히 충족한다** — 상위·중간대
20곳 중 X 가 1곳이다.

**경계 구간 50% 는 교과서적 결과다.** 컷을 옮길 근거가 없다. 발견 C 에서 의심했던
Layer 2 구제 경로(월 8건 미만 통과 238곳)도 여기 포함되어 있었고, 그중
라온숨·후탄 등은 O 였다. **구제 경로를 막지 않는다** — 막았으면 좋은 카페를
버렸을 것이다.

### X 이유 분포가 결정적이다

```
5건  취향      -> 알고리즘 문제 아님 (스펙 13.1)
1건  동네 카페 -> Layer 2 컷 / Layer 4 임계
```

경계 구간 X 5건이 **전부 "그냥 취향이 아니다"** 였다. 즉 경계에서 걸러야 할
것을 못 걸러낸 것이 아니라, 알고리즘이 옳게 올린 것을 사람이 안 간다고 한
것이다. **주차 불만은 상위·중간대에서 0건** — p2 프롬프트의 주차 하향 조정이
유효했다는 뜻이다.

## 2. 골든셋이 잡아낸 구조적 버그 — 조건부 배제를 상태로 굳혔다

오탈락 3건 중 **공원스크립트**(용인 고기리, 대형카페·브런치·뷰맛집)를 추적하니
근거가 이랬다.

```
"예쁜 공간에 비해 주차장은 조금 협소한 편"  ->  주차 C  ->  excluded_auto
```

스펙 7.3 은 주차 C 를 **"기본 숨김. 서울 도심 보기 토글에서만"** 으로 정의한다.
배제가 아니다. 그런데 `classify` 가 `passesGate` 를 그대로 호출해 C 를 그 자리에서
`excluded_auto` 로 굳히고 있었다. 그리고 `weekly-suggest` 는 `status !== 'active'`
를 먼저 걸러내므로 **`--city` 를 켜도 C 카페는 후보에 들어올 수 없었다.**

```
실측: npm run suggest -- --city  ==  npm run suggest   (완전히 동일한 결과)
      주차 C 로 굳어버린 카페 50곳
```

**`--city` 는 죽은 옵션이었다.** 도심 카페를 보는 유일한 경로가 막혀 있었다.

### 수정

되돌릴 수 없는 배제와 조건부 배제를 분리했다.

| 함수 | 판정 | 쓰는 곳 |
|---|---|---|
| `passesHardGate` | 태그 0개 · 주차 D | `classify` (상태를 굳힌다) |
| `passesGate` | 위 + 주차 C(cityMode 아니면) | `weekly-suggest` (읽는 시점) |

**조건부 배제는 상태로 굳히지 않고 읽는 시점에 판정한다.** 굳힌 50곳은
`active` 로 복구했다.

```
복구 후   active 174곳
          일반 모드 후보 124곳 / 도심 모드 후보 174곳
도심 모드에서만 보이는 곳: 양평 소풍, 언더스탠드커피, 종로 아모르나폴리,
                          에이라운드 ...
```

**교훈**: "기본 숨김"과 "배제"는 다르다. 전자를 상태에 쓰면 후자가 된다.

## 3. 남은 오탈락 2건 — 고치지 않는다

| 카페 | 탈락 사유 | 판단 |
|---|---|---|
| 강변테라스 (양평) | 검색 정밀도 4% | **식별 실패이지 판정 실패가 아니다.** 상호가 일반명사라 블로그 검색으로 이 카페를 특정할 수 없다. 컷을 낮추면 진짜 식별 불가한 곳이 들어온다. 동 이름을 붙인 2차 조회 같은 별도 수단이 필요하다 |
| 브런치 카페 물러남 (양평) | 월 0.6건 | 화제량이 실제로 거의 없다. 컷을 낮추면 동네 카페가 쏟아진다. **오통과율 5% 를 지키는 대가로 수용한다** |

두 건 모두 임계값으로 해결할 수 없다. 임계값을 움직이면 오통과율이 오탈락률과
맞바꿔지기만 한다. 오탈락 30% 중 **1건은 버그였고 2건은 구조적 한계**다.

## 4. 회귀 기준선

앞으로 프롬프트·태그 임계·스코어 공식을 고칠 때마다 이 40곳으로 재측정한다.

```
npm run label -- --report
```

지켜야 할 선:

| 지표 | 현재 | 기준 |
|---|---|---|
| 동네카페 오통과율 | 5% | **10% 이하** (성공 기준 2) |
| 경계 구간 통과율 | 50% | 30~70% |
| 오탈락률 | 30% | 악화시키지 않는다 |

프롬프트 판본을 올리면 `classify --redo-stale` 로 40곳을 재추출한 뒤 다시
`--report` 를 돌린다. 라벨은 `kakaoPlaceId` 기준이므로 재추출해도 유지된다.
