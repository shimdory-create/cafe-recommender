## 1. 실행 결과 요약

```
npm run discover -- --region 양평군 --skip-harvest
   신규 123곳 / 자동배제 4곳 / 전체 127곳

npm run buzz -- --limit 12
   갱신 12곳 / 실패 0

npm run classify -- --limit 12

npm run suggest

```

## 2. 발견 A — `seatsEstimate` 가 거의 항상 null 이다

판정 통과한 9곳 **전부** `seatsEstimate: null` 이었다.

원인은 명확하다. 실제 블로그 스니펫에 좌석 수가 숫자로 나오는 경우가
드물다. LLM 은 규칙대로 "추측하지 마라"를 지켜 null 을 냈다. **추출은
올바르게 동작했다.**

### 영향

1. **`assignTags` 는 문제없다.** `seatsOf()` 폴백(대형 120 / 중형 60 /
   소형 20)이 설계대로 작동한다.
2. **스펙 10절의 "카드 상단 고정 3종"이 깨진다.** `좌석 규모` ·
   `주차 등급` · `메뉴 레벨` 중 좌석 규모를 표시할 수 없다.
   "갈지 말지를 3초에 결정하게 하는 정보"의 3분의 1이 비어 있다.

### 계획 3(웹앱) 전에 결정해야 할 것

| 안 | 내용 | 평가 |
|---|---|---|
| A | 카드 3종을 `규모(대형/중형/소형)` · `주차` · `메뉴`로 교체 | **추천.** scale 은 거의 항상 채워졌다. 숫자 좌석 수는 애초에 얻기 어렵다 |
| B | 좌석 수를 얻으려 스니펫을 더 많이 넣는다 | 토큰 비용이 늘고 여전히 원문에 없으면 소용없다 |
| C | 좌석 수 칸을 비워둔다 | 3초 판단 UI 가 무의미해진다 |

**A 를 권한다.** 스펙 10절의 카드 3종을 `규모 · 주차 · 메뉴`로 고치고,
`seatsEstimate` 는 있으면 보조 표시하는 값으로 내린다.

## 3. 발견 B — 태그 분포가 지나치게 균일하다

통과 9곳의 분포:

```
대형카페        8/9
뷰맛집          9/9   <- 전부
주차 A          9/9   <- 전부
정원마당형       7/9
디저트특화       6/9
```

**`뷰맛집` 9/9 와 `주차 A` 9/9 는 변별력을 의심할 신호다.**

가능한 해석이 두 가지이고, **지금 어느 쪽인지 알 수 없다:**

1. **정상** — 양평 외곽 대형카페는 실제로 대부분 강뷰이고 주차가 넉넉하다.
   표본이 양평군 하나라 지역 특성이 그대로 반영된 것일 수 있다.
2. **관대함** — `viewStrength >= 3` 임계가 낮거나, LLM 이 "창밖이 보인다"
   정도를 3점으로 주고 있다. 주차도 "주차장 있다"를 A 로 올리고 있을 수 있다.

### 지금 튜닝하지 않는 이유

표본이 9곳이고 지역이 하나다. 여기서 임계값을 올리면 **근거 없는 추측으로
좋은 카페를 버릴 위험**이 있다. 이것이 정확히 스펙 13.1절 골든셋이
측정하도록 설계된 대상이다.

### 계획 2에서 측정할 것

- 서울·인천·경기 여러 지역으로 표본을 늘린 뒤 태그 분포를 다시 본다
- 골든셋 경계 구간에서 `뷰맛집` 태그가 붙은 곳들의 O/X 비율을 본다
  - `X` 가 많으면 → `viewStrength` 임계를 4로 올린다
  - `O` 가 많으면 → 정상이며 양평 특성이었다
- `주차 A` 판정의 정확도는 `parkingEvidence` 원문을 사람이 읽어 검증한다
  (`npm run inspect` 가 이미 출력한다)

## 4. 기타 관찰

- **`하우스베이커리` 정밀도 50%** — 상호가 일반적인 조합("하우스" +
  "베이커리")이라 오염이 있다. `isAmbiguousName` 의 사전에는 없어서
  `ambiguousName` 플래그가 붙지 않았다. 골든셋 경계 구간으로 들어가지
  않으므로 **사전 확장을 검토할 후보**다.
- **`pending_extraction` 111곳** — `--limit 12` 로 잘라서 남은 것이며
  정상이다. 전체를 돌리려면 `buzz` 를 먼저 전량 실행해야 한다
  (`classify` 는 화제량 스냅샷이 없으면 `skipped` 로 미룬다 — 설계대로).
- **실행 시간** — `classify` 12곳에 약 16초. 카페당 약 1.3초로
  Gemini flash-lite 선택이 유효했다. 1,200곳이면 약 26분.

## 5. 계획 2 착수 전 준비

```
1) npm run discover                     # 65개 시군구 전량 (그물 A+C)
2) npm run buzz                         # 전량 화제량 (약 1,500 호출)
3) npm run classify -- --limit 200      # 며칠에 나눠 실행
4) 그 뒤 골든셋 40곳 층화 추출 -> O/X 판정
```

2)와 3) 사이에 하루를 두는 것이 안전하다. `classify` 는 화제량 스냅샷이
있는 카페만 처리하므로 순서가 뒤바뀌면 전부 `skipped` 가 된다.
