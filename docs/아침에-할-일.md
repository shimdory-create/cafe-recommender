## 남은 것

### ⓪ GitHub 토큰 다시 만들기 (2분) — 별점 기능용

밤에 만든 토큰이 GitHub 에서 **401 Bad credentials** 로 거부됩니다. 형식은
정상이었으니 값이 잘못 복사됐거나 다른 계정에서 만든 것입니다.

[github.com/settings/personal-access-tokens/new](https://github.com/settings/personal-access-tokens/new)

- 우측 상단 프로필이 **`shimdory-create`** 인지 먼저 확인
- **Resource owner** 를 `shimdory-create` 로 선택
- Repository access → Only select repositories → `cafe-recommender`
- Permissions → Repository → **Contents: Read and write**, **Secrets: Read and write**
- 생성 화면의 **복사 버튼**으로 복사 (화면 글자를 마우스로 긁지 마세요)

받은 값을 두 곳에 넣습니다:
1. `.env` 의 `GITHUB_TOKEN=` 뒤 (제가 검증하고 Actions 시크릿을 등록합니다)
2. Vercel → Settings → Environment Variables → `GITHUB_TOKEN` 추가 → Redeploy

**이걸 안 하면**: 추천·리스트·다녀온 곳은 다 되지만 별점·다녀왔어요 체크가
"아직 설정 전" 으로 나옵니다. 그리고 매일 자동 수집이 안 돌아 목록이 멈춥니다.



### ⓪-b GitHub Actions 시크릿 (2분) — 매일 자동 수집용

토큰이 계속 안 되면 이건 손으로 넣는 편이 빠릅니다. **이게 없으면 매일 새벽
수집이 돌지 않아 목록이 오늘 자로 멈춥니다.**

`https://github.com/shimdory-create/cafe-recommender/settings/secrets/actions`

**New repository secret** 을 두 번 눌러 추가합니다. 값은 `.env` 파일에서
복사하세요 (메모장으로 열면 보입니다).

| Name | 값 |
|---|---|
| `KAKAO_REST_API_KEY` | `.env` 의 같은 이름 값 |
| `GEMINI_API_KEY` | `.env` 의 같은 이름 값 |

넣고 나면 **Actions 탭 → daily-buzz → Run workflow** 로 한 번 눌러보면
동작을 바로 확인할 수 있습니다.

### ① Vercel 배포 — 밤에 진행했습니다

주소를 알려주시면 `.env` 의 `SITE_URL` 에 넣고 금요일 정오 카톡을 완성합니다.
(아래는 다시 해야 할 경우의 절차입니다)

[vercel.com/new](https://vercel.com/new)

1. **Import Git Repository** 에서 `cafe-recommender` 선택
   - 안 보이면 **Adjust GitHub App Permissions** → `cafe-recommender` 체크 → Save
2. **Root Directory** 를 `web` 으로 변경 ← 이게 중요합니다
3. **Environment Variables** 세 줄:

   | Name | Value |
   |---|---|
   | `ACCESS_CODE` | 가족 접근 코드 (예: `bupyeong2026`) |
   | `GITHUB_TOKEN` | `.env` 에 넣어둔 그 토큰 |
   | `GITHUB_REPO` | `shimdory-create/cafe-recommender` |

4. **Deploy** → 나온 주소를 저에게 알려주세요

> 환경변수를 안 넣어도 배포는 됩니다. 다만 접근 코드 없이 열리고(누구나 볼 수
> 있음) 별점 저장이 안 됩니다. 세 줄 넣는 편이 낫습니다.

### ② 주소 알려주기 → 금요일 정오 카톡

주소를 주시면 제가 카톡 문구를 완성하고 **금요일 정오 발송**을 걸겠습니다.
발송 전에 문구를 보여드립니다.
