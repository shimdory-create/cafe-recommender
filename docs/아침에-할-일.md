정상이었으니 값이 잘못 복사됐거나 다른 계정에서 만든 것입니다.

[github.com/settings/personal-access-tokens/new](https://github.com/settings/personal-access-tokens/new)

- 우측 상단 프로필이 **`shimdory-create`** 인지 먼저 확인
- **Resource owner** 를 `shimdory-create` 로 선택

- Permissions → Repository → **Contents: Read and write**, **Secrets: Read and write**

받은 값을 두 곳에 넣습니다:
1. `.env` 의 `GITHUB_TOKEN=` 뒤 (제가 검증하고 Actions 시크릿을 등록합니다)

**이걸 안 하면**: 추천·리스트·다녀온 곳은 다 되지만 별점·다녀왔어요 체크가

## 배포에서 걸린 것 (참고용, 조작 불필요)

Vercel 빌드가 세 번 실패했고 원인이 각각 달랐습니다. 전부 코드 문제였고
고쳐서 푸시했습니다.

1. **Turbopack 이 동적 파일 접근을 거부** — 로컬 파일 저장의 경로 탐색을
   "정적 분석 불가" 로 보고 프로젝트 전체를 번들에 넣으려 하다 실패.
   배포 번들에서 분리(동적 import)하고 `turbopackIgnore` 를 달았습니다.
2. **zod 를 찾지 못함** — web 이 파이프라인 스키마에서 타입을 가져오는데,
   그 파일이 web 밖이라 모듈 해석이 위로 올라갑니다. Vercel 은 web 에서만
   설치하므로 못 찾습니다. zod 를 web 의존성으로 올려도 해결되지 않습니다.
3. **그래서 경계를 넘는 import 를 걷어냈습니다** — web 에 순수 인터페이스
   파일을 두고, 스키마와의 불일치는 파이프라인 테스트가 잡습니다.
