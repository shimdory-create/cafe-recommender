무료 키라 청구가 발생할 경로가 없고, 실제 피해는 "남이 쿼터를 쓰면 수집이 조용히

매일 07:40 에 봅니다. 경보가 걸리면 **GitHub 이 계정 메일로 알립니다** (PC 가 꺼져
있어도 닿습니다). 그리고 **금요일 정오 카톡 마지막 줄에 상태가 붙습니다** —
`자동수집 정상` 이면 정상, `점검 필요: …` 면 손볼 것이 있다는 뜻입니다.

한 가지 중요한 조정: **쿼터 소진 자체는 경보가 아닙니다.** 무료 티어는 하루 한도를
쓰면 429 를 주고 멈추는 것이 정상이라, 그걸로 매일 메일을 보내면 사흘 뒤부터 아무도
열지 않습니다. 남이 우리 키를 쓰는 경우는 "429 가 왔다" 가 아니라 **"한 곳도 못
했다"** 로 드러납니다 — 그것만 경보로 잡습니다.

감시에는 일부러 API 키를 주지 않았습니다 — 감시가 키에 의존하면 키가 문제일 때
감시부터 죽습니다.

## 참고: 키를 바꾸고 싶어지면 (5분)

### Gemini API 키 교체 — 어젯밤 대화창에 노출됐습니다

`.env` 내용을 채팅에 붙여주셔서 키가 대화 기록에 남았습니다. 유출 사고는
아니지만, 무료 키라도 남이 쓰면 **우리 일일 쿼터를 대신 소진합니다** (그러면
신규 카페 판정이 멈춥니다).

[aistudio.google.com/apikey](https://aistudio.google.com/apikey)

1. 기존 키 삭제 → **Create API key**
2. 새 값을 `.env` 의 `GEMINI_API_KEY=` 뒤에 붙이기
3. GitHub → Settings → Secrets → Actions → `GEMINI_API_KEY` 업데이트

> 앞으로 키는 채팅에 붙이지 말고 "`.env` 에 넣었어" 라고만 알려주세요.
> 제가 파일에서 직접 읽습니다.

## 밤에 잡은 것 세 가지

셋 다 "돌아가는 것처럼 보이지만 안 돌아가는" 종류였습니다.

**① 자동 수집이 오늘 밤 전부 실패할 상태였습니다.** 스크립트가 `.env` 파일을
**필수**로 읽게 되어 있었는데, 그 파일은 열쇠가 들어 있어 GitHub 에 올리지
않습니다. 서버에는 파일이 없으니 첫 줄에서 죽습니다. "있으면 읽는다" 로 바꾸고,
서버와 똑같은 조건(파일 없음 + 열쇠는 환경변수)에서 실제로 돌려 확인했습니다.
일요일 길찾기 잡은 열쇠 한 줄이 빠져 있어 함께 채웠습니다.

**② 체크한 직후가 "안 눌린 것" 처럼 보였습니다.** 방문 기록 읽기에 30초 캐시가
있어서, 다녀왔어요를 누르고 다녀온 곳을 열면 비어 있고 추천 목록에도 그 카페가
그대로 남아 있었습니다. 캐시를 없앴습니다 — 월 몇 번 열리는 페이지라 매번 읽어도
한도에 한참 못 미칩니다.

**③ 읽기 실패가 "기록 없음" 으로 보였습니다.** 저장소를 못 읽어도 응답은
정상(빈 목록)이라, 다녀온 곳 탭이 통째로 비어 보일 수 있었습니다 — 가족에게는
기록이 지워진 것으로 보입니다. 이제 실패는 실패라고 말하고, 그럴 때는 마지막으로
알던 목록을 그대로 보여줍니다.

**품질 기준선 재측정**: 골든셋 40곳 그대로 — 동네카페 오통과율 5%, 경계 통과율
50%. 아깝게 탈락한 3곳도 확인했는데 셋 다 설계 의도대로였습니다 (후기가 월 0.6건
뿐이라 "요즘 뜨는 곳" 이 아님 / 이름이 흔해서 화제량 측정이 안 됨 / 주차 어려움).
