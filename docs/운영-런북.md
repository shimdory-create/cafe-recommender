# 운영 런북 — 뭔가 이상할 때

이 서비스는 결제도 업데이트도 없이 도는 것을 전제로 만들었다. 그래도 언젠가는
멈춘다. 그때 **5분 안에 원인을 찾는 것**이 이 문서의 목적이다.

전제: 조작이 필요한 일은 거의 없다. 아래 표에서 증상을 찾아 그 줄만 읽으면 된다.

---

## 신호는 두 곳으로 온다

| 경로 | 언제 | 조건 |
|---|---|---|
| **GitHub 메일** ("daily-watch failed") | 이상이 생긴 날 아침 | PC 가 꺼져 있어도 온다 |
| **금요일 정오 카톡 마지막 줄** | 매주 금요일 | 이 PC 의 Claude Code 가 켜져 있어야 |

카톡 마지막 줄이 뜻하는 것:

| 줄 | 뜻 | 할 일 |
|---|---|---|
| `자동수집 정상` | 이상 없음 | 없음 |
| `주의: 판정 지연` | 무료 쿼터가 일찍 끊긴 정도 | 없음 (정상 범위) |
| `점검 필요: …` | 손봐야 한다 | 아래 표에서 찾는다 |
| **줄이 아예 없다** | 옛 버전이 돌았거나 발송 경로가 바뀜 | 아래 "카톡이 안 온다" |

---

## 증상별 대응

### 워크플로가 아예 안 돌았다

GitHub 무료 스케줄러는 혼잡하면 **예약을 조용히 버린다.** 실패가 아니라
실행 자체가 없어서 메일도 안 온다 (2026-08-24 에 classify·watch 가 그랬다).

하루 누락은 정상 범위다 — 다음 날 이어서 처리된다. 이틀 연속이면 감시가
`수집 멈춤` 으로 잡는다. 급하면 손으로 돌린다:

[Actions 탭](https://github.com/shimdory-create/cafe-recommender/actions) →
워크플로 선택 → **Run workflow**

### 목록이 며칠째 그대로다

```bash
npm run watch
```

`수집 멈춤` 이나 `수집 조기 중단` 이 나오면 워크플로가 안 돈 것이다.
[Actions 탭](https://github.com/shimdory-create/cafe-recommender/actions) 에서
빨간 X 를 열어 **실패한 단계 이름**을 확인한다. 지금까지 깨진 곳은 전부
마지막 `데이터 커밋` 단계였고, 규칙은 `scripts/commit-data.sh` 한 곳에 있다.

수동으로 한 번 돌리려면 Actions 탭 → 워크플로 선택 → **Run workflow**.

### `점검 필요: 판정 정체` — 신규 카페가 안 늘어난다

판정은 Gemini 무료 쿼터를 쓴다. **하루 한도까지 쓰고 멈추는 것은 정상**이고,
다음 날 이어서 처리한다. 그런데 **한 곳도 못 한 날이 이어지면** 남이 우리 키를
쓰고 있을 수 있다 (키가 2026-08-21 대화에 노출된 상태를 알고서 유지 중).

그 경우 키를 새로 발급한다 — [aistudio.google.com/apikey](https://aistudio.google.com/apikey)

1. 기존 키 삭제 → Create API key
2. `.env` 의 `GEMINI_API_KEY=` 교체
3. GitHub → Settings → Secrets and variables → Actions → `GEMINI_API_KEY` 수정

카카오 키도 같은 절차다 (카카오 개발자센터 → 내 애플리케이션 → 앱 키).

### `점검 필요: 화제량 측정 부족` — 순위가 낡았다

카카오 블로그 검색이 막혔다는 뜻이다. 일 30,000 한도에 우리는 1,100 을 쓰므로
쿼터 문제일 가능성은 낮다. 키가 유효한지 먼저 본다.

```bash
npm run check-keys
```

### 링크를 눌렀는데 화면이 안 열린다

Vercel 문제다. 가장 흔한 원인은 **Vercel Authentication 이 다시 켜진 것**이다
(프로젝트를 다시 만들면 기본값으로 살아난다). 켜져 있으면 가족이 Vercel 로그인
화면을 만난다.

Vercel → 프로젝트 → Settings → Deployment Protection → **Vercel Authentication
= Disabled**

### 별점·다녀왔어요가 "설정 전" 이라고 나온다

`GITHUB_TOKEN` 이 만료·삭제됐다. 만료 없는 토큰을 쓰고 있으므로 누가 지운
경우다. 새로 만들어 **Vercel 환경변수**와 `.env` 두 곳에 넣는다.

- 권한: Contents(읽기·쓰기), Secrets(읽기·쓰기), Actions(읽기·쓰기)
- Resource owner: `shimdory-create`

### 카톡이 안 온다

발송은 카카오톡 커넥터를 쓰기 때문에 **금요일 정오에 이 PC 의 Claude Code 가
켜져 있어야** 한다. 꺼져 있었으면 그것이 원인이고, 링크는 언제 눌러도 최신이다.

완전 자동으로 만들려면 카카오 OAuth 토큰을 서버에 저장하는 작업이 필요하다
(아직 하지 않았다 — 필요해지면 그때).

### `폐업 확인 필요` 경고가 떴다 (maybe_closed)

카카오 장소 검색에서 21일 넘게 안 보이는 카페다. 발굴 잡은 새 카페만 넣으므로
폐업해도 목록에 남는다 — 그래서 주 1회 다시 찾아본다.

**바로 지우지 않는다.** 검색 순위 밖으로 밀렸거나 상호가 바뀐 것일 수도 있다.
지도에서 직접 확인한 뒤 내린다.

```bash
npm run hide -- "카페 이름"
```

되살리려면 `npm run hide -- --restore "카페 이름"`.

### 특정 지역 카페가 적다

대개 **수집이 안 된 것이 아니라 판정이 밀린 것**이다. 먼저 확인한다.

```bash
npm run health
```

그 지역만 몰아서 판정하려면:

```bash
npm run classify -- --limit 250 --order near
```

`near` 는 집에서 가까운 순이다. 평소에는 하루 몫의 30% 가 자동으로 거리순에
배정되므로(스펙 11.5) 며칠 지나면 저절로 메워진다.

### 열람용(동료용) 주소 — 이미 만들어져 있다

```
https://cafe-view-shim6.vercel.app
```

Vercel 프로젝트 `cafe-view` 가 가족용과 **같은 저장소**를 본다. 커밋이
올라가면 두 곳이 함께 배포된다. 환경변수는 없다.

쓰기 차단은 **주소로 판단한다** — host 가 `cafe-recommender` 로 시작하지
않으면 서버가 403 을 준다. 그래서 열람용에 무엇을 설정하든 쓰기는 열리지
않는다.

| | 가족용 | 열람용 |
|---|---|---|
| 주소 | `cafe-recommender-git-master-shim6` | `cafe-view-shim6` |
| 머리말 배지 | 없음 | **열람 전용** |
| 별점·다녀왔어요 | 가능 | 버튼 없음 · API 403 |
| 별점 표시 | 실시간 | 빌드 시점 (하루 단위) |

다시 만들 일이 생기면: [vercel.com/new](https://vercel.com/new) →
`shimdory-create/cafe-recommender` Import → 이름 `cafe-view` → Root Directory
`web` → Deploy.

**만든 직후 Vercel Authentication 을 꺼야 한다.** 새 프로젝트는 기본으로
켜져 있어서 동료가 Vercel 로그인 화면을 만난다 (2026-08-25 실제로 겪었다).

Settings → Deployment Protection → Vercel Authentication = **Disabled**

### 열람용에서 별점이 안 보인다

토큰 없이도 **빌드 시점 후기**가 보이게 해 뒀다 (하루에 한 번 갱신). 그것도
안 보이면 배포가 옛 코드인 것이다 — Vercel 에서 최신 커밋으로 다시 배포한다.

실시간으로 보이게 하려면 열람용 프로젝트에 **읽기 전용** GitHub 토큰을
넣는다 (Contents: Read). 쓰기는 어차피 host 로 막혀 있다.

### 판정이 전부 실패한다 (`source_failing`)

모델이 은퇴한 경우다. `gemini-3.1-flash-lite` 는 언젠가 사라진다.

`src/llm/` 의 모델 이름을 현재 무료 모델로 바꾸고 `npm test` 를 돌린다.
그다음 `npm run label -- --report` 로 품질이 유지되는지 확인한다
(기준선: 오통과율 5%, 경계 통과율 50%).

## 아무것도 안 했는데 멈출 수 있는 경로

결제 없이 도는 구조에서 진짜 위험은 돈이 아니라 **부패**다.

| 경로 | 대비 |
|---|---|
| 모델 은퇴 | 감시가 `source_failing` 으로 잡는다. 이름 한 줄 교체 |
| GitHub 액션 버전 만료 | v7 / Node 24 로 올려둠 (2026-08-21) |
| 토큰 만료 | 만료 없는 토큰. 만료를 걸면 그날 조용히 멈춘다 |
| Actions 무료 한도 (월 2,000분) | **2026-09월에 실제로 소진됐다** — 9/25 밤부터 2,079/2,000분으로 한도를 넘어 리셋(10/1)까지 daily-watch를 포함한 모든 워크플로가 조용히 멈췄다(실제 청구는 $0, 예산 $0가 정상 작동한 것). 원인은 `daily-buzz-restaurant`(활성 식당 전체를 매일 재측정) 하나가 식당 수가 4,200여 곳으로 늘면서 하루 6분→22분까지 커진 것 — 이게 월 예산의 약 30%를 혼자 썼다. **2026-09-28에 구조적으로 고쳤다**: `src/jobs/daily-buzz.ts`·`restaurant-daily-buzz.ts`·`spot-daily-buzz.ts`에 `ACTIVE_PER_DAY` 상한(카페 1,600·식당 1,500·가볼곳 900)을 추가해, `pending`과 같은 회전 방식(오래 안 잰 것부터)으로 active도 돌게 했다 — 데이터가 계속 늘어도 하루 비용이 여기서 더 안 커진다. 그래도 [GitHub 사용량](https://github.com/settings/billing/summary)은 가끔 확인한다 — weekly-discover 등 다른 잡도 데이터가 늘면 조금씩 커질 수 있다. 한도를 넘으면 돈이 나가지 않고(예산 $0로 막아둠) 그 달 남은 기간 동안 **모든 워크플로가 조용히 멈춘다** — daily-watch도 같이 멈추므로 이 경우엔 카톡도 안 온다(GitHub이 이메일로 별도 안내할 수는 있음). |

## 오래 못 볼 예정이라면 (2026-09-23 점검)

당장 고장은 아니지만, 사람이 오래 안 볼수록 커지는 것들이다.

| 항목 | 왜 지금 살펴야 하나 |
|---|---|
| **API 키 교체** (`GEMINI_API_KEY`, `KAKAO_REST_API_KEY`) | 2026-08-21 대화 노출을 "감시하며 유지"하기로 했었다 — 그 전제는 **사람이 매일 본다**였다. 몇 주~몇 달 아무도 안 보는 기간에는 위험 프로필이 다르다. 지금 교체를 권한다 (절차는 위 "판정 정체" 항목). |
| **`폐업 확인 필요`(maybe_closed) 누적** | liveness는 **절대 자동으로 안 내린다** (설계 의도 — 멀쩡한 곳을 잘못 지우는 게 더 나쁘다). 즉 사람이 `npm run hide`를 안 돌리면 폐업한 곳이 계속 추천 목록에 남는다. 지금은 2곳뿐이지만, 몇 달 뒤엔 꽤 쌓여있을 수 있다 — 돌아왔을 때 `npm run watch`로 한 번에 확인. |
| **.git 저장소 크기** | 자동 커밋마다 생성 JSON(현재 `site-restaurant.json`만 5.6MB)을 통째로 다시 써서 커밋한다 — 순위가 매일 바뀌어 거의 매번 전체가 새로 보인다. 지금 `.git`이 ~290MB, 최근 며칠 하루 수십MB씩 늘고 있다. 이 속도면 GitHub이 저장소 용량을 문제 삼기까지(몇 GB대) 대략 몇 달 걸린다 — 급하진 않지만 "언젠가 손볼 것" 목록에 올려둔다. |
| **모델 은퇴** | `gemini-3.1-flash-lite`가 사라지면 판정이 전부 실패로 조용히(watch 메일은 옴) 멈춘다. 새 무료 모델 이름으로 교체하는 절차는 위에 있음 — 되돌아왔을 때 판정이 하나도 안 늘어있으면 이것부터 의심. |
| **금요일 카톡이 끊김** | 이 PC의 Claude Code가 안 켜져 있으니 당연히 안 온다. 사이트 자체는 계속 갱신되니 가족은 그냥 사이트로 확인하면 된다 — 걱정할 일 아님. |

## 자주 쓰는 명령

```bash
npm run watch          # 운영 이상 점검 (키 없이 돈다)
npm run audit          # 데이터 정합성 점검 (키 없이 돈다)
npm run requeue -- --dry   # 컷이 바뀐 뒤 되살릴 배제분 미리보기
npm run liveness       # 폐업 감지 — 카카오에 아직 있는지 다시 찾아본다
npm run normalize      # 시군구를 주소 기준으로 정정 (멱등)
npm run health         # 데이터 현황과 소스 상태
npm run notify         # 카톡 문구 미리보기 (발송 안 함)
npm run label -- --report   # 골든셋 품질 기준선
npm run inspect -- "카페명"  # 한 곳의 판정 근거 확인
```

Bash 로 돌릴 때는 `export PATH="/c/Program Files/nodejs:$PATH"` 를 먼저 붙인다.
